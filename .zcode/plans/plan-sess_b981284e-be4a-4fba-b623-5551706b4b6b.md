## 3. Core design decisions
1. **Event bus is the spine.** Every meaningful operation (run start/end, agent invocation, model call, tool call/result, retry, checkpoint, handoff, approval, usage) emits a typed Pydantic Event on one async bus. Terminal UI, web UI, JSON output, and the persistence layer all consume the same stream — runtime never knows about presentation. Storage overhead kept low: events append to a session-local JSONL, never re-enter model context.
2. **Context minimization, concretely:** repo index built once and cached (tree + sizes, not contents); system prompts are small role-scoped templates composed by the assembler, never one universal prompt; agents exchange `TaskResult` Pydantic models (summary + changed files + key findings + errors), never raw histories; history beyond a threshold is summarized at checkpoints; a `context report` (CLI + `om-harness status`) shows exactly what was sent to the model and why.
3. **Provider layer stays thin.** PydanticAI already unifies OpenAI/Anthropic/Google; om-harness adds: key/availability detection, model-string registry with per-provider capability flags, task-type routing (e.g. explore→cheap/fast model, implement→strong model, review→reasoning model) with user overrides and `FallbackModel` chains, and graceful degradation when a capability is missing.
4. **Tool safety model.** Tools carry a `Permission` level; the approval policy engine (config: `auto`, `ask`, `allowlist`, plus per-tool overrides) gates mutating/destructive tools. In non-interactive/CI runs the default is deny-with-report. Shell/git-write tools have timeouts, output caps, and path scoping to the repo root. No secrets ever reach events, checkpoints, or logs (redaction at the bus).
5. **Orchestration is small and explicit.** Planner heuristic picks the simplest strategy that can finish the task; coordinator uses `asyncio.TaskGroup` + semaphore + per-task timeouts + cancellation + exponential backoff with jitter; fan-in aggregates deterministically (declaration order, not completion order). Specialist results merge via structured `TaskResult`s.
6. **Durability:** sessions persist under `<repo>/.om-harness/` (auto-gitignored): session JSON + JSONL events + checkpoints (compact state: plan, task statuses, summaries, working-notes — not full transcripts). `resume` rebuilds a scoped context from the checkpoint.
7. **No credentials in code**: keys only from env (`OPENAI_API_KEY`, `ANTHROPIC_API_KEY`, `GOOGLE_API_KEY`, optionally read via `OM_HARNESS_*` config), `.env.example` documents them; tests never need keys.

## 4. TDD execution phases (tests written first in each phase, then minimum implementation, then refactor)
1. **Scaffold**: pyproject/uv sync, ruff+mypy config, package skeleton, Makefile, git init, CI workflow. Gate: `make check` green on empty-but-linted skeleton.
2. **Models + config + events**: all core Pydantic contracts, env/config loading precedence, EventBus fan-out/ordering/redaction tests.
3. **State**: store atomicity, session lifecycle, checkpoint save/load, resume reconstruction (incl. crash-mid-write recovery), no-secret-in-store test.
4. **Tools**: each tool against fixture repos (temp git repos); permission levels; approval policies (auto-allow read-only, gate destructive, deny in CI); timeouts; structured ToolResult errors; shell output caps.
5. **Context**: repo index caching, budget accounting, scoped assembler (asserts: repo info not re-sent, summaries replace old history, TaskResult-only inter-agent exchange).
6. **Providers**: registry/availability, routing table + overrides, fallback chain, MockProvider driving the whole runtime without network.
7. **Runtime runner**: agent factory, run loop emitting correct event sequences, usage capture, retry-on-ModelRetry, cancellation, token budget enforcement via UsageLimits.
8. **Orchestration**: strategies with deterministic async tests (sentinel scheduling proving parallel calls are NOT serialized and fan-in order is stable); planner picks single-agent when possible; retry/recovery; coordinator timeout/cancellation races.
9. **CLI**: Typer commands with CliRunner; `--json` output; `doctor` (repo/git/provider diagnostics); `init`/`status`/`resume`/`providers`/`agent`.
10. **Terminal UI + REPL**: compact renderer using event stream components; non-interactive run prints status lines + final summary only; verbose shows full traces.
11. **Web reference client**: FastAPI + SSE reusing EventBus + session manager; API-level tests; one-page chat client (send, stream, approve, session list).
12. **E2E**: complete mocked flow — init session in temp repo → plan → inspect → edit a file → run tests → summary → checkpoint → resume; plus one real-cred-gated integration test per provider.
13. **Docs + final verification**: README, `docs/architecture.md` + `docs/design.md` (Mermaid diagrams: component overview, run lifecycle, orchestration flows, context assembly, event flow; explicit tradeoffs), CONTRIBUTING, `.env.example`; then **clean-environment verification**: fresh `uv sync`, `make check`, e2e demo run, and a contributor walkthrough of the README commands.

## 5. Non-goals (v1)
No databases/queues/distributed infra, no MCP integration (extension point documented only), no fine-tuning/eval harness, no speculative agent marketplace. Extension points documented: new provider (one adapter entry), new tool (registry entry + permission), new strategy (StrategyKind + planner rule), remote runtime (store/bus interfaces), web app (same event stream/session model).
